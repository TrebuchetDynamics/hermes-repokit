## Finding that motivated the run

Both deployments were installed by RepoKit releases that embedded OpenViking
(`efe7f40` through `2fc8bfc`). After `0bd3b14` removed that provider, current
RepoKit no longer recognized its own output:

- every SOUL those releases wrote read as owner-customized, so convergence
  would never have upgraded them (`0bd3b14` had edited historical SOUL sources
  in place);
- their Compose files (one `REPOKIT_OPENVIKING` marker line) read as foreign,
  so `install` and `start` refused.

Fixes: `3b1de97` archives every shipped SOUL generation as exact templates
pinned by SHA-256; `dd4699d` restores recognition of OpenViking-era Compose,
pinned by 34 golden renders from `0bd3b14^`.
